# Default M2 production contract

`vibe_ic_one_shot_runner` invokes `mixed_signal_power_domain_run` after a
successful M1. Default selects Yosys once: read the supplied Liberty blackboxes,
read the routed Verilog, check hierarchy, and write native connectivity JSON.
No alternate arm, global execution controller, insertion or waiver is involved.

Inputs are `phase3/mixed_signal/top_merged.gds`, exactly one
`phase2/stage2/constraints/<top>.upf`, `phase3/stage3/pnr/<top>_pnr.v`,
`phase3/stage3/pnr/routed.def` (or `<top>.def` when routed.def is absent), and
the project's `input/pdk/liberty/*.lib`. Direct invocation may supply explicit
`--liberty` paths. Conflicting corners/cell definitions are refused. Top is
the fixed runner's resolved top, or the unique UPF filename for direct calls.

The supported UPF subset is literal, one command per line: `upf_version`,
`set_design_top`, `create_power_domain -elements {instances/ports ...}`,
the supply definition/connection commands, `set_domain_supply_net`,
`create_supply_net ... -domain ... -voltage <positive number>`,
`add_power_state <domain> -state {ON -voltage <number>}` or `{OFF}`,
`set_isolation` and `set_level_shifter`. Domains must explicitly enumerate
every flat routed instance and top signal port, with one stated voltage.
Dynamic Tcl, include_scope, nested hierarchy, general supply/logic expressions,
PST/multiple voltages, unresolved directions, inout signals and unplaced or
mismatched DEF instances are refused. The existing L21 UPF handoff often lacks
elements/voltages; it cannot establish this basis and returns NOT_READY/FAIL.

Protection requires a real cell in the native connectivity path and matching
placed DEF instance/type. Liberty must declare `is_level_shifter` with a data
pin and compatible `level_shifter_type`, or `is_isolation_cell` with data and
enable pins. Isolation must lie in a domain that remains powered. A strategy
declaration alone, a suggestive instance name or an off-path cell never counts.
All ordinary inputs and protection control inputs are audited, bit by bit;
only the explicitly identified protection data path is traversed transparently.

The producer writes `reports/analog/mixed_signal/{power_domain,level_shifter,
isolation,pd_connectivity}.json` and `power_domain_run.json`, schema
`vibeic.mixed_signal.m2.v1`. Native JSON, script and transcript reside in
`power_domain_tool/`. The receipt binds SHA256s of every input and tool/sidecar
output and records the Yosys creator/container. A new invocation withdraws
the previous receipt/sidecars and native JSON before running. Missing output,
bad JSON, nonzero tool exit, concurrent input changes or unsafe crossings
cannot publish a successful receipt.

The first blocking M2 gate uses `--check-only`: check every digest and rederive
the expected sidecars from the bound native JSON, UPF, DEF and Liberty. Then
the existing crossing, level-shifter, isolation and UPF strategy gates run.
The verifier writes only its audit, never required producer outputs. Return
codes are 0 verified, 1 invalid/unsafe/stale evidence, 2 missing basis/tool.

This proves placed structural protection, with merged-GDS identity bound. It
does not prove supply-pin connectivity, analog voltage tolerance, isolation
control sequencing, power-off behavior, DRC/LVS or electrical signoff. M1's
existing KLayout/Magic/netgen producer and blocking merge gate remain in place.
M3's AMS/interface SI outputs and M4's owner signoff still need genuine native
evidence; this change leaves them NOT_READY and preserves their gates.

The checked-in `programs/tests/fixtures/m2_placed` is a neutral synthetic
four-cell routed fixture. Its GDS was generated by KLayout from four placed
rectangles. It exercises Yosys and the fixed caller, not physical signoff.
